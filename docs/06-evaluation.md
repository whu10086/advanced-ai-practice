# 怎样判断 AI 技巧是否有效

[返回首页](../README.md)

衡量技巧的单位是具体任务。先描述期望行为，再保留样例，最后比较改动。模型给自己的回答打高分不能单独证明流程可靠。

## 最小比较方法

1. 先固定 10 条开发样例：包含正常输入、缺失信息、冲突来源、无关资料与恶意指令文本。
2. 为每条写明确预期：字段、可接受答案、支持证据、何时应停止或请求人工处理。
3. 保存基线输出与环境：模型、参数、提示、流程版本、日期、检索结果和工具响应。
4. 每次只改变一个主要因素，例如提示结构或检索方法。比较成功率、失败类型、耗时与费用。
5. 用新的留出样例做最后检查。优化过程中反复查看的题目不能再充当独立测试集。

[示例 JSONL](../templates/evaluation-set.jsonl) 中是本项目原创的教学样例，不是真实业务数据，也不代表经过验证的基准。

## 三类任务怎样评分

| 任务 | 自动检查 | 人工检查 | 建议记录 |
| --- | --- | --- | --- |
| 代码变更 | 相关测试、构建、类型检查；按项目实际要求选取 | 是否满足场景；是否扩大范围；是否易读、可维护 | 通过的验收场景数 / 总场景数 |
| 文档工作流 | JSON schema、必填字段、来源 ID、重复执行行为 | 摘要是否漏掉限制；是否忠于原文 | 格式有效率、证据支持率、待人工处理数 |
| 研究问答 | 引用 ID 存在、页码字段完整、实验代码运行 | 原文是否支持主张；材料不足是否正确说明 | 正确率、引用支持率、拒答比例、错误原因 |

引用支持率可定义为“人工确认被引用材料支持的主张数 / 已抽查且带引用的主张数”；没有引用的关键主张应额外计入缺证据数量。明确分母，避免只抽查容易的样例。

## 工具如何选择

- [Promptfoo](https://github.com/promptfoo/promptfoo)：适合建立 prompt/provider/test cases，比较多种配置和断言。
- [Ragas](https://github.com/vibrantlabsai/ragas)：适合 RAG 和生成任务的指标、测试数据生成。指标的含义要回到当前官方文档核对。
- [DSPy](https://github.com/stanfordnlp/dspy)：适合有清楚指标和数据之后的程序优化；保存优化数据与留出数据的划分。
- [Langfuse](https://github.com/langfuse/langfuse)：记录 trace、调用量和耗时，帮助解释为什么某次运行更差。

模型评审可以扩大初筛，但先用一批人工评分样例校准。保留原始输出和评分理由，查看模型评审与人工分歧最大的情况。
