# AI Coding：从让模型写代码到完成可验收变更

[返回首页](../README.md) · [资源总表](05-resource-catalog.md)

适合会使用 Git、能运行一个简单项目、用过至少一种编程助手的人。目标是独立完成一个小功能或缺陷修复，并解释改了什么、为何正确、如何回滚。

## 学习顺序

| 顺序 | 阅读入口 | 专门看什么 | 建议练习 |
| --- | --- | --- | --- |
| 1 | [Aider 官方用法](https://aider.chat/docs/usage.html)，从仓库 README 进入 repomap、Git、lint/test | 模型如何获得仓库信息；哪些文件应加入上下文；怎样接入已有检查命令 | 在一个熟悉的小项目中修复单个缺陷 |
| 2 | [Codex 开源仓库](https://github.com/openai/codex) 的 README 与贡献文档 | 本地执行、代码差异和验证；安装要求以当前官方说明为准 | 用相同任务比较两种上下文组织方式 |
| 3 | [Spec Kit](https://github.com/github/spec-kit) 的 process、templates 与官方文档 | 规格如何贯穿设计、任务、实现和收敛 | 把“加导出功能”写成 4—6 条验收场景 |
| 4 | [OpenSpec](https://github.com/Fission-AI/OpenSpec) 的示例规格、变更目录 | 已有项目中的增量需求、变更归档 | 在老项目加一个小功能；和 Spec Kit 二选一落地 |
| 5 | [Superpowers](https://github.com/obra/superpowers) 的 Basic Workflow 与技能目录 | 需求澄清、计划、系统调试、完成前验证 | 把自己的成功步骤压缩成一页操作卡 |

Aider 的代码最近推送时间较核验日已有数月，应先确认自己的模型接口和环境兼容性。Codex/Aider 的开源许可覆盖相应仓库代码，调用的模型或账号套餐另行计费。

## 最值得掌握的五个做法

### 1. 先把验收场景写出来

“帮我优化项目”很难验证。换成：“CSV 导出增加 UTF-8 BOM；中文在表格软件中正确显示；空数据仍导出表头；原 JSON 导出行为保持兼容。”把输入、输出和边界条件写进[任务模板](../templates/coding-task.md)。

### 2. 按问题组织上下文

先给入口文件、相关接口、已有测试和复现步骤。让 AI 说明将读取哪些文件以及原因，再按需补充。上下文过长时保存阶段结论：已确认事实、相关文件、决策理由、下一步和未验证假设。

### 3. 把探索、设计和修改分开记录

探索阶段要求解释现状与风险；设计阶段确定变更方案和验收；修改阶段执行任务。每个阶段保留简短产物，方便中断后恢复。简单修改可以一轮完成，无须强行引入完整框架。

### 4. 用反馈定位失败

遇到报错时提供完整的相关错误、触发输入和环境。要求先形成可验证假设，再做最小修改，再重跑相关检查。防止把报错文字改掉、跳过检查或者修改测试期望来掩盖缺陷。

### 5. 用差异与运行证据收尾

检查 `git diff`，执行与变更有关的测试、构建或人工场景。记录实际命令和结果，清楚区分“通过”“失败”“未执行”。最后保留一次小而完整的提交，能复现也能撤回。

## 一个完整练习

选择自己已有的 CLI 或网页项目，完成“按标签筛选并导出结果”。建议安排 3—5 小时，前提是项目已可运行；零代码基础先补 Git 和调试。

1. 写需求：正常筛选、无结果、非法输入、中文内容四类场景。
2. 让 AI 查找最相关的模块，说明当前数据流。
3. 用 Spec Kit 或 OpenSpec 组织任务；也可先手工填写模板。
4. 分两次修改：先筛选，再导出；每次检查差异并验证。
5. 交付代码提交、验证记录、已知限制和下一次改进点。

验收：四类场景有实际验证结果；无关文件没有被重写；能说明新增依赖是否必要；别人能按 README 重现功能。

## 什么时候继续进阶

当你能稳定完成上述练习，再尝试 worktree 隔离、CI 中的自动检查、工具接口和多人协作。多 Agent 与自动长任务需要额外的任务隔离、成本记录与合并检查；先用单 Agent 建立可靠流程更容易定位问题。

推荐后续阅读：[Goose](https://github.com/aaif-goose/goose) 的扩展和 MCP 实例、[Promptfoo](https://github.com/promptfoo/promptfoo) 的评测配置，以及本指南的[评测方法](06-evaluation.md)。
